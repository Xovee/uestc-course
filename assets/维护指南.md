# 维护指南

本文件维护仓库操作细节。任务范围、人工审查和提交批准以根 [AGENTS.md](../AGENTS.md) 为准；公开收录标准见[仓库协议](仓库协议.md)。所有命令从仓库根目录运行。

## 按任务选择流程

| 任务 | 读取与操作 |
| --- | --- |
| 新增本地或 Issue/PR 资源 | 本文“资源入库”至“README 更新”，目标课程 README、对应模板及收录标准 |
| 整理既有课程或分类 | 本文“归属与命名”“README 更新”，仅处理用户指定范围 |
| 修改规则、贡献说明或模板 | 本文“规则维护”“验证”，核对主文件及直接引用入口 |
| 修改自动化代码或测试 | 相关实现、测试、[质量检查](../.github/workflows/quality.yml)与本文“验证” |
| 维护静态网站 | `site/`、`tools/build_static_site.py` 和 [Pages 工作流](../.github/workflows/pages.yml)；代码变更按代码检查验证 |

## 资源入库

### 1. 确定批次与来源

- 先看 `git status --short`，区分原有改动和本次工作。必要时先运行只读 audit，保存摘要以区分既有问题。
- 原始资料放在 `_incoming/`。存在多个批次时，仅操作当前批次子目录；文件夹本身也可能是一项资源，不把其他批次误当资源包。
- Issue/PR 入库先读正文和评论，再整理附件。明确给出的课程、分类、作者、教师和不完整说明是高优先级元数据；与资源正文冲突时列出双方证据，不静默覆盖。
- 下载时间、原文件名、贡献者描述都不是对考试时间、官方答案或转载许可的独立证明。

### 2. 生成并审查计划

单批次入口：

```powershell
python tools/ingest_resources.py prepare --incoming _incoming --output _incoming/plan.json
```

多批次时将两处路径替换为同一个批次目录，例如：

```powershell
python tools/ingest_resources.py prepare --incoming _incoming/本批次 --output _incoming/本批次/plan.json
```

- 逐项审查 `plan.json` 的来源、候选归属、目标名称、元数据、筛查结果和 `apply`。`prepare` 的推断只是草案；`scan` 不做完整内容筛查，不能替代入库审查。
- 工具会忽略入口目录中的 `plan.json` 和名称以点开头的条目；其他导出、报告和辅助文件放在批次外，避免被当作资源。
- 筛查命中风险或未充分检查的条目按根 AGENTS 保持 `apply: false`。在计划中补充审查说明，保留检查范围、证据及用户决定，不删除风险记录来制造“低风险”。
- 内容筛查目前仅对文本、PDF 和 DOCX 做有限文本提取，每个文件最多筛查 200,000 字符，每个文件夹最多取 30 个文件；不覆盖全部图片、版面、批注和其他嵌入内容。`low` 仅表示该次自动检查未发现问题。
- 入库前检查全部拟收录内容。图片与扫描页需视觉检查；DOC/PPT/PPTX、压缩包、音视频等采用合适的只读方式检查。不运行来历不明的宏、脚本或可执行文件；检查不了的部分明确留待审，不用抽样代替全项收录判断。
- 试题必须核对正文中的考试信息。`exam_metadata_requires_content_review` 可在内容核实充分后处理；仍无法可靠确定的元数据由用户决定。新课程名称、创建范围已经由用户明确且模板可确定时，不重复确认；其他新课程候选保持待审。

### 3. 应用已审查条目

```powershell
python tools/ingest_resources.py apply --incoming _incoming --plan _incoming/plan.json
```

多批次使用与 prepare 相同的入口和计划路径。只对已获授权、检查充分的条目设置 `apply: true`。

- 全部 `apply: true` 条目先统一预检。拒绝来源越界、空来源或来源等于入口目录，拒绝目标越出 `课程目录`、重复目标、已有目标、字段包含路径分隔符，以及旧分类 `历年真题`。
- 校验失败时不得先写入其他条目。现有工具提供的是**校验失败前不写入**，不保证磁盘故障等运行时错误自动回滚；中断后先检查实际文件和 README，再决定恢复，不盲目重跑或删除。
- `apply` 不复核内容风险和用户授权，不自动完成旧分类迁移、历史重排或试题元数据判定；这些由维护者在审查及收尾时完成。
- 工具目前只向 `课程目录` 入库。`考研目录` 按用户指定范围人工整理，沿用相同收录标准和分类表格；不得通过修改计划路径绕过工具范围。

### 4. 验证、提交与清理

- 对照计划核对实际文件或文件夹、README、命名、元数据和受影响链接，完成本文“验证”中的适用检查，然后按根 AGENTS 请求本批发布批准。
- `_incoming/` 清理条件：该批次已经整理完成且资源及 README 已提交，或用户明确批准清理该批次。清理前核对已处理来源清单、目标路径与内容一致性；只清理对应原始来源，不另行归档，保留待审、未处理和其他批次文件。
- 保留本批计划用于核对与去重；计划不是资源，也不据此证明已经提交或推送。失败的推送和未完成的 Issue 后续操作分别报告。

## 归属与命名

### 目录与范围

- 课程资源置于 `课程目录/<课程名>/<分类>/`，常用分类为 `复习资料`、`历年试题`、`作业`。
- `历年试题` 是唯一现行试题分类名。处理到仍使用 `历年真题` 的课程时，在本次涉及的课程内迁移并修复链接；目标已存在时先核对内容，不覆盖或自动合并冲突。
- 新课程创建课程 README、实际需要的分类目录和分类 README，不预建空分类；无可靠介绍时保留简短占位，不编造课程事实。
- SQL 上机练习通常归复习或练习资料；用户明确指定或内容证明为实际考试时才归 `历年试题`。
- 普通新增仅修改新增文件、相应 README 条目和必要链接，保留旧资源命名及历史条目的相对顺序。用户明确要求整理课程或分类时，才在该范围统一新旧命名、格式和排序，不扩展到其他分类或独立历史表格。

### 文件名与考试信息

- 保守清理空格、非法字符和重复分隔符，保留原意与扩展名，不凭空补年份、学期、答案性质、教师、作者或来源。
- 非试题资源默认以课程名开头；目标分类已有明确命名惯例时沿用。
- 试题优先使用 `年份学期-考试类型-答案状态-补充信息.ext`，例如 `2026年春-期末考试-无答案-计院-回忆版.pdf`。目标试题分类已有一致课程名前缀时可保留；模板示例不覆盖此规则。
- 从正文确定年份、学期、考试类型、形式及答案状态；无法读内容时文件名仅作候选证据，仍需人工审查。例如 `2007-2008学年第一学期` 对应 `2007年秋`，第二学期对应 `2008年春`。
- 无可靠日期时保留未知或使用 `时间不明`；不把文件 mtime 当考试日期。学期、考试类型缺失时不猜填。
- 答案或批注不能证明为官方时，在文件名注明 `仅非官方答案` 或 `含非官方答案`，README 备注说明 `非官方整理` 或 `参考答案非官方`。
- 教师、作者、不完整说明通常放 README 备注；`闭卷`、`A卷`、`回忆版` 等按目标表格及命名规则记录，保留必要信息。

### 压缩包

- `历年试题` 不直接收录压缩包，唯一保留情形是已检查且只包裹图片截图的 ZIP。该例外也须完成内容审查；只有满足此条件时才设置 `allow_exam_archive: true`。
- 其他试题压缩包解压到本批次的独立检查目录，先核对成员路径和内容，再按目标课程惯例整理文件或文件夹。解压文件仍在 `_incoming/` 内，原包在批次清理前保留。
- README 列最终入库文件或文件夹，不列未入库原包；来源项不得同时覆盖原包和同一份解压结果。

## README 更新

- `课程目录/0-模板` 是唯一课程及标准分类模板来源；[模板索引](模板/README.md)和考研分类模板只提供入口。新建或修复表格时精确沿用标题、表头和分隔行，包括空格，例如 `文件名|来源 | 文件类型|文件大小|备注`。
- 示例行只解释结构，不复制到真实课程。`文件名` 单元格通常不含扩展名，实际文件保留扩展名；文件夹保留完整文件夹名。
- 写入前读取目标表格的实际表头，按列填值，不固定位置。已有非标准列保留其事实信息；不随意增加 `科目`、`考试形式`、`答案` 等列。
- 作者已有可靠信息而目标无 `作者` 列时写入 `备注`；无 `备注` 列时可保守增加该列，并检查所有行列数。不因模板检查提示而丢弃已知事实。
- 来源沿用 `GitHub Issue`、`PR`、`河畔`、`Local` 等词汇，不发明 `Issue #153` 这样的来源标签；编号、原始链接和额外说明可放备注。
- 备注中的来源网址用简短 Markdown 链接，例如 `来自[河畔](原始网址)`。单元格保持单行，换行替换为空格，原始 `|` 转义或替换。
- 有更新时间列时使用来源文件 mtime，不用执行当天日期；目录资源的工具默认值取目录及其后代中可读 mtime 的最大值。下载、解压或转换可能改变这些时间，需核对；原修改时间无法追溯时注明可得时间的来源，不伪造历史日期。mtime 与试题学期分别记录。
- 新增到已按日期倒序排列的表格时插入相应位置；其他表格保留旧条目相对顺序。明确整理范围内，有可核实日期的条目倒序，未知日期置后，已有更明确局部约定时沿用。保持同一表格的日期含义一致，不混用考试时间和文件更新时间。
- 工具当前把新行插在表头下，**不会自动按日期放到正确位置**；应用后需要核对并调整本次新增行。
- 多个 `文件名` 表格须按根 AGENTS 先确认目标，脚本不支持此类自动写入；确认后在指定表格人工编辑。
- 教材未设计统一展示结构，不自动写入条目；先确认收录范围、版权和展示方式。模板以外的在线资源表保留既有结构，不凭示例批量新建。

## 验证

### 资源、规则及模板变更

1. 核对本批计划（如有）、目标文件、README、命名、元数据、表格列数及受影响链接。规则变更核对引用入口、授权边界和工具实际能力；模板变更还要检查生成的 README 不含示例行或未替换占位。
2. 运行下列检查，并读取 audit 的各项结果：

```powershell
python tools/ingest_resources.py audit
git diff --check
```

3. audit 当前检查标准课程分类的模板差异、旧试题分类、空目录、重复扩展名、重复条目、README 与本地文件对应关系，以及部分模板和 Markdown 链接问题。排序检查只解析文件名中的日期，不核对更新时间列的完整日期。教材不按普通资源目录检查；考研资源的逐项对应和任意链接锚点仍需人工核对。
4. audit 是只读报告，**退出码为 0 不代表没有问题**；空问题列表才说明其覆盖范围内未发现问题。对非空项区分本次引入、既有问题、已确认的局部表格差异，不为清空报告改动范围外资源。

### 自动化代码或测试变更

以下四项均须执行；模板变更影响生成逻辑时，也运行相关现有测试：

```powershell
python -m unittest discover -s tests
python -m py_compile tools/build_static_site.py tools/ingest_resources.py tools/repository_size_report.py tests/test_build_static_site.py tests/test_ingest_resources.py tests/test_repository_size_report.py
python tools/ingest_resources.py audit
git diff --check
```

- 按改动补充必要的功能验证；质量 CI 另有仓库大小报告和静态索引的冒烟检查。
- 修复本次失败后重跑受影响检查；通过后没有新改动或证据不重复运行。不能完成的检查报告原因和未验证部分。
- 主分支推送会触发质量 CI 及独立的 Pages 部署；本地检查不代表远端 CI 或网站发布已经成功。

## 规则维护

- 授权边界改根 AGENTS，操作步骤改本文，公开收录标准改仓库协议，版权与权益事项改对应专项文件，表格结构改唯一模板；随后更新直接引用入口。
- `.github/CONTRIBUTING.md`、Issue 模板、`assets/prompt.txt` 保持简短，只引用主规则或收集输入，不复制完整验证命令、命名规定或发布权限。
- 更新规则时核对受影响的文档、模板、代码、测试和 CI，避免把尚未实现的能力写成现状。只调整本次必要部分；表格结构改变需说明迁移范围，不自动全库迁移。
- `assets/版权交流/`、版权讨论与已停止的资源完善计划属于历史参考或状态记录；保留原文，不将其当成现行收录授权。`课程目录/readme_change.py` 和 `file_count.py` 是旧辅助脚本，不作为日常批量维护入口。
- 仓库规则使用相对链接和通用路径，不写设备专属目录、私人记录或无关应用配置。交付用具体变更和验证结果说明完成情况。
